Tool delivery receipt (v1)

Un agent qui paie une route x402 reçoit souvent un tool_result sans attestation : la réponse n'est ni signée ni vérifiable par défaut. Kairos propose trois briques gratuites, complémentaires :

  • relationship memory — se souvenir de qui on a payé ;
  • tool result digest — hasher canoniquement le livrable ;
  • tool delivery receipt — lier paiement (route, montant, adresses) et digest dans un JSON portable que l'acheteur garde.

Schéma (gratuit)

GET https://x402.agentindex.world/.well-known/tool-delivery-receipt.json
GET https://x402.agentindex.world/tool-delivery-receipt/sample

Valider un reçu

POST https://x402.agentindex.world/tool-delivery-receipt/validate
{"receipt": { … }, "content": …}

Le champ optionnel content recalcule le digest (même algorithme que /tool-result-digest) et renvoie digest_verification.match.

MCP

Sur https://x402.agentindex.world/mcp :

  • tool_delivery_receipt_schema
  • validate_tool_delivery_receipt

La validation ne stocke rien côté serveur — c'est un format que d'autres agents peuvent adopter dans leur propre journal ou mémoire de relation.
